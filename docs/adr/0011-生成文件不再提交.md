# 0011 生成文件不再提交进 main（待定：所有者点头后再做）

- 状态：**待定**（11-10 所有者同意「先写 ADR」；实现要等点头）
- 日期：2026-11-10
- 相关：Issue #152（第 5 级）· PR #151（用 `.gitattributes` 缓解）· ADR 0010

## 背景
`南伴球_PWA.html` / `南伴球_Web.html` / `南伴球_后台.html`（由 `src/` 拼出）、`server/migrations/_bundle.sql`（由迁移拼出）、`schema.sql`（手工与迁移同步）都提交在仓库里。多人并行开发时，这些文件每个 PR 都会改，必然冲突。#151 让合并时先留一边、合并后重新生成，冲突不再要人处理，但每个 PR 的 diff 里仍有几千行生成内容，评审要绕开它们，仓库体积也在涨。

## 方案
1. **生成文件在 CI / 部署时生成，不提交**：`tools/build.mjs`、`tools/migrate_bundle.mjs` 在 Pages 构建（`tools/site.mjs`）和测试前运行；仓库里 `.gitignore` 掉这四个文件。
2. **`schema.sql` 由迁移生成**：新增 `tools/schema_dump.mjs`，在空库依次执行全部迁移后导出结构；`db-parity` 对比的对象不变（线上库 vs 迁移结果）。
3. **直接打开 HTML 看的人**：本地 `node tools/build.mjs` 一次；预览站始终是最新的。

## 好处
PR 里只剩手写源码，冲突类型只剩真正的逻辑冲突；`pr_merge.sh` 的「提交前检查生成文件一致」和 `post-merge` 钩子可以删掉。

## 风险与要先验证的事
- Cloudflare Pages 构建要能跑 node 脚本（现在已经跑 `tools/site.mjs`，应该可以）。
- 测试和 `smoke` 读的是生成后的 HTML：测试入口要先生成；`ci_paths` 要加上。
- `schema.sql` 生成要和 `db-parity` 结构指纹逐项一致，否则先不动它，只做前三个文件。
- 回退：把四个文件重新提交、去掉 `.gitignore` 即可。

## 分步
①先只做三个 HTML + `_bundle.sql`（风险低）→ ②观察一周冲突数 → ③再做 `schema.sql`。每步一个 PR，先草稿，所有者点头后合。
