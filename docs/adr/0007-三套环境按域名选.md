# 0007 三套环境，按域名选择

- 状态：已接受
- 日期：2026-11-03

## 背景
需要在不动真用户数据的前提下真机验证有风险的改动。

## 决定
| 环境 | 域名 | 数据 |
|---|---|---|
| 正式 | `nanbanqiu.app` | 正式库 `nanbanqiu-au` |
| 测试 | `*.nanbanqiu-preview.pages.dev`（分支预览，页面带「测试环境」横幅） | 测试库 `nanbanqiu-staging` |
| 预览站根 | `nanbanqiu-preview.pages.dev` | 正式库登录 + 演示数据 |

由前台按域名选择（`nbqEnvOf`，单测 `unit/env_select`）。线上 `/api/version` 报告迁移是否都已执行，以它为准。测试环境推送使用单独的发送程序 `nanbanqiu-notify-staging` 和固定地址 `staging.nanbanqiu-preview.pages.dev`。

## 后果
- 好处：风险较大的改动先在测试库上真机验证（发布流程 B）。
- 代价：正式有的部件（发送程序、推送公钥、密钥）测试环境都要有；两个库的结构必须一致（`db-parity`）。

## 什么情况下回头重看
增加成员 / 环境，或测试库与正式库出现反复不一致。
