# 0010 常设授权：红线以内协作者自助合并，所有者只管红线和规则

- 状态：已接受
- 日期：2026-11-10　· 拍板：所有者 SMG562（11-10 22:22 墨尔本，「全部同意……给予协作者更多权限，尽可能自动化，减少问我、申请权限」）
- 相关：协作实践.md §11 · CODEOWNERS · Issue #113 #152 · PR #151

## 背景
11-10 开着 15 个 PR，5 个以上在等所有者一个人评审或真机。`tools/`、`.github/`、`.claude/`、全部规则文件都要所有者批准，连文档整理和测试辅助脚本也要等；一个 PR 来回四轮才合进去。瓶颈是评审，不是写代码。

## 决定
1. **红线（只有所有者能做，CODEOWNERS 机器拦）**：
   ① 正式库执行迁移、改数据、删数据；② 部署、密钥、发送程序（`deploy-notify.yml`、`wrangler.jsonc`、`worker/`、`notify-worker/`）；③ 隐私文案与对外政策（`privacy.html`、`隐私清单.md`）；④ 闸门本身（`pr_merge.sh`、`gate.sh`、`precommit.sh`、`.githooks/`、`db-parity.yml`、`pr-checklist.yml`、`pr_body_check.mjs`、`CODEOWNERS`、`doc_budget.json`）；⑤ 规则与业务（`CLAUDE.md`、`AGENTS.md`、`docs/constitution.md`、`业务规则.md`、`docs/adr/` 的「已接受」）；⑥ 删除文件、强推。
2. **红线以外一律自助合并**，不用问所有者：作者（协作者或 AI）在满足条件后自己跑 `bash tools/pr_merge.sh <号>`。条件：tests-fast + tests 对同一提交都绿；PR 描述核对通过；**独立复核**（见 3）；需要真机的项（登录、推送、迁移、启动、Service Worker、键盘）已由所有者在「每日集成预览」里确认。
3. **独立复核**：由另一个没看过本次过程的 AI 会话只读复核，在 PR 上留一条「独立复核：通过 <提交号前 7 位>」，写明看了什么、风险和回退。适用于：公共层（`0130 0140 0155 0495`）、接口与用户数据读写、迁移 SQL、`tools/` 与 `.github/` 里不在红线的文件、`.claude/skills/`。纯文档、文案、样式微调不需要。
4. **所有者的工作变成三件事**：①定红线和规则（本 ADR）；②执行红线动作（正式库迁移、部署、隐私文案点头）；③每天一次真机清单。其余只看决定卡和周报。
5. **决定卡**：每个 PR 描述顶部固定五行——改了什么 / 影响面 / CI 状态 / 怎么回滚 / 需要所有者做什么（没有就写「无」）。由 `tools/decision_card.mjs` 生成（后续 PR）。
6. **GitHub 一侧（11-10 已设置）**：个人账号仓库没有 Maintain 角色（协作者即 Write）、也没有合并队列，所以：分支规则「必须审批人数」= 0、保留「Code Owners 审核」；仓库设置打开「Allow auto-merge」和「合并后删分支」，用自动合并代替合并队列。

## 后果
- 红线文件之外的 PR 不再等所有者；等待时间从「天」降到「CI 时间」。
- 风险从"所有者逐个看"转移到"CI + 独立复核 + 红线"。代价：独立复核要多开一个会话，多花一点 token；换来的是所有者不再是单点。
- 出事照旧对事不对人：同类第二次必须升级成自动检查；稳定性闸门（协作实践.md §12）照旧。

## 否决的方案
- **全部放行**：红线里的动作不可逆（正式库、密钥、隐私承诺），不能靠事后补救。
- **维持现状**：评审单点，在制品只增不减。
- **只给 AI 授权、协作者不变**：同一批事情，不该因为谁写的而不同；分级按风险，不按人。
