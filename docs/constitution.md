# 南伴球工程宪法

这十条是「不轻易改」的底线。其他规矩（`CLAUDE.md`、`协作实践.md`、`开发规矩.md`）可以随经验调整，这里的改动要走 PR + 所有者批准 + 一条 ADR 说明理由。
每条后面写了**谁来保证**——能自动拦的由机器拦，拦不住的靠评审清单。

1. **一个任务一个分支，一个 PR 一个目的。**合并后删分支，不复用。〔协作实践 §1；评审〕
2. **`main` 始终可部署，CI 红了先修再做别的。**〔分支保护 + `pr_merge.sh` 核对 CI〕
3. **测试可以被绕过，但必须留下原因并事后补上。**`NBQ_UNTESTED`、`--no-verify` 都要写原因；同一个理由出现第二次，就改工具，不再靠例外。〔pre-push；逃逸缺陷台账〕
4. **数据库只往前走：先加、再迁、后删，分在不同的发布里；已合并的迁移不可修改。**〔`tools/migration_audit.mjs`；`db-parity`〕
5. **用户能改的数据必须写服务器，刷新后还在、换设备还在。**〔`persist_audit`；入口清单；`e2e_fullstack`〕
6. **重大决定先有 ADR，与已有 ADR 冲突先停下来问。**〔`docs/adr/`；CODEOWNERS〕
7. **一件事只有一个事实来源。**需求看 Issue，接口看 `tests/spec/api_spec.md`，库看 `server/migrations/`，业务规则看 `业务规则.md`，架构看 ADR，进度看 `进度记录.md`；助手发现缺规则，开 Issue，不自己创造规则。〔协作实践 §0〕
8. **AI 提议，人批准。**库结构、公共接口、架构、密钥、部署、正式库操作必须由人批准；AI 生成的代码，提交人必须读懂每一行。〔协作实践 §11 分级；CODEOWNERS〕
9. **用户看得见的改动，真机验过才算完。**键盘、弹层、输入法、Service Worker 类改动没有真机验证不算完成。〔PR 清单；逃逸缺陷 11-05〕
10. **出事先止血再查因，对事不对人；同类问题第二次出现，必须变成自动检查。**〔`逃逸缺陷.md` 升级规则；出事处理手册〕

## 怎么保持这份宪法有用
- 每条都应该能回答「它拦住过什么」。每季度回看一次（见 `协作实践.md` §13）：从没拦住过、又有成本的，提议删掉；反复出事但宪法没覆盖的，提议加一条。
- 宪法不超过 10 条。想加一条，先想想能不能并进已有的，或者做成自动检查而不是条文。
