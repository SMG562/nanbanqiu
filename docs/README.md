# 文档地图

每份文档只做一件事，改行为的 PR 同时改对应文档。核心文档有体量上限（`tests/spec/doc_budget.json`，`tools/doc_budget.mjs` 检查）：超了就拆分或精简，不是调高上限；上限只降不升，调高要所有者批准。

| 想知道 | 看哪里 | 谁维护 |
|---|---|---|
| 项目的底线 | [`docs/constitution.md`](constitution.md) | 所有者 |
| 助手 / 新人怎么开工 | `AGENTS.md` → `CLAUDE.md` | 所有者 |
| 新人踩坑自查、前台状态、空状态文案 | `.claude/skills/`（`collaborator-pitfalls` 等） | 所有者 |
| 怎么协作、评审、拆 PR | `CONTRIBUTING.md`、`协作实践.md` | 所有者 |
| 所有者不在时怎么继续 | [`所有者不在时.md`](所有者不在时.md) | 所有者 |
| 为什么这么设计（架构决定） | [`docs/adr/`](adr/README.md) | 提议人写、所有者批准 |
| 业务规则 | `业务规则.md` | 所有者 |
| 开发规矩的来历、命令、例子 | `开发规矩.md` | 谁改规矩谁更新 |
| 测试怎么跑、有哪些 | `tests/README.md` | 谁改测试谁更新 |
| 现在做到哪、下一步 | `进度记录.md`（旧的在 `进度记录_历史.md`） | 所有者 |
| 以后再做 / 要人定的事 | GitHub Issues | 所有人 |
| 出过什么问题、怎么拦住的 | `逃逸缺陷.md` | 发现人写，同类第二次升级成自动检查 |
| 线上出事怎么办、怎么回滚、高风险操作步骤 | `出事处理手册.md` | 所有者 |
| 上线前必须做的事 | `上线加固清单.md`、`真机清单.md` | 所有者 |
| 隐私与合规 | `隐私清单.md` | 所有者 |
| 多城市扩展 | `地区扩展设计.md` | 所有者 |
