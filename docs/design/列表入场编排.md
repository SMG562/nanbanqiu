# 列表入场与新帖编排（11-20 场边「静光」定稿）

来源：#492 第 5 项之后，所有者提出「首屏多张图 / 每一条帖子都要有秩序、有呼吸感地依次出现，新帖到达也要同一套气质」。从 #501（单图柔和显影）一路做了 5 版原型到定稿。
可播放的定稿原型（左右两部手机并排、可放大、可慢放、含「全流程演示」）：`原型_列表入场编排.html`（打开后左 = 静光，右 = 呼吸，新帖强调 = 中）。
通用的动效方法见 `动效与引导设计.md`，审美总纲见 `美学与品味.md`；本文只写「列表类内容怎么入场」，以及 11-20 当天每个选择和理由，将来别的列表（球局、通知、相册、球场页）直接照搬。

## 一、用户此刻的心理
刚点进场边的人想知道的是「今天球场周围有没有人、热不热闹」，最怕冷清和被打扰。所以：
- 进来时，内容应该「一点点亮起来」，像球场灯一盏盏亮，而不是一股脑蹦出来，也不是白屏等很久。
- 往下刷了一会儿后来了新帖，用户正在看别的内容，**绝不能抢他的位置**；新内容只能轻轻举手示意。
- 点了「有新内容」，用户期待的是「带我回去，并且让我看清哪几条是新的」，而不是瞬间跳走、一堆东西同时弹出。

## 二、起点：当时代码的问题（读代码得出，不是猜）
- `#501` 只做了「图到一张放一张」排队（间隔 70ms）：顺序取决于网络谁先到，不是上下顺序；只管图片，不管整条帖子。
- 点「↑ N 条新动态」胶囊（`flushNew`）：新帖直接 `prep()` 插进去、`scrollTop=0` 瞬间跳回顶部，没有任何过渡。
- 别人的新帖走 `birth()`：「…」输入气泡 + 带弹簧过冲的气泡长大（`cubic-bezier(.22,1.28,.42,1)`）。这套很活泼，但和「安静、高级」的整体气质不是一类。

## 三、所有选择与理由（按尝试顺序）
| 尝试 | 做法 | 结果 | 结论 |
|---|---|---|---|
| 只淡入 | 只有 opacity | 稳，但没有「被点亮」的感觉，一整屏同时淡入很平 | 保留作对照 |
| 只升起 | 淡入 + 升 8px | 干净，但没有质感和呼吸 | 保留作对照 |
| 灯亮（v1） | 升 18px + 模糊 + 整块暖白泛光 | 所有者：有秩序有动感，但不优雅 | 太用力，淘汰 |
| 微光（v3） | 顶边一道暖金细线从左划到右 | 所有者：**像车内彩色灯带，抢眼、低陋、与整体色调不协调** | 彩色线条一律淘汰 |
| **静光（定稿）** | 表面由略暗变回本色 + 一道和主题同色、几乎看不见的柔光 | 所有者：「可以定稿」 | **采用** |
| 呼吸 | 没有掠过的光；卡片从略小略低略暗舒展到本来大小，阴影由紧变松 | 所有者：默认配置不错，但要「少一点浮光」 | 保留作对照，可复用 |
| 叠层 | 位移更大、底色更暗、更长 | 更强调层次，节奏最缓 | 保留作对照 |

关键教训：
1. **「光」不要有颜色，也不要是一条线**。暖金线在白卡片上像灯带，是最典型的「想高级却显廉价」。光要和主题同色（浅色用品牌绿 `23,107,77`，深色用中性白），强度低到要凑近才看得出。
2. **节奏比特效重要**。先放慢（所有者两次说「更慢、更平静」），再去掉特效，才出来「高级」。
3. **「少」比「多」难**：最终定稿比 v1 少了模糊、少了大位移、少了彩色光，只剩 6px 位移 + 表面亮起 + 极淡柔光。
4. **一次只给一个高光**。整套里唯一的「光」是那道柔光；位移、阴影、分层都是「物理感」而不是「光效」。

## 四、定稿参数（改之前先对照原型，不要凭记忆）
**每张卡片**（「静光」）
| 项 | 值 | 说明 |
|---|---|---|
| 起始状态 | `opacity 0`，下移 6px，缩放 .994，底色 = 卡片色 84% + 背景色 16%，阴影收紧 | 几乎看不出「从哪来」，只觉得「浮上来」 |
| 落稳 | 单张时长 1.5s；位移 ×1.3；底色与阴影 ×1.8 | 位移最快收住，底色和阴影慢慢跟上，所以有「被轻轻放下」的感觉 |
| 缓动 | 位移 / 阴影 `cubic-bezier(.19,1,.22,1)`（快起、长尾）；透明度 / 底色 `cubic-bezier(.33,0,.2,1)`（柔） | 位移和透明度分开用两条曲线 |
| 内容分层 | 头像行 0ms → 正文 +120ms → 图 +240ms → 互动行 +360ms，**只淡入不位移** | 位移只给卡片一次，里面的东西不再动，否则会「抖」 |
| 柔光 | 104° 渐变，18%–82% 透明到峰值再透明，背景尺寸 300%，时长 = 单张 ×3.6 | 浅色峰值透明度 .022，深色 .03 |
| 图片显影 | 从 scale 1.025、blur 5px、饱和 .78、亮度 .97 到清晰；透明度 1.7s、位移 2.2s、滤镜 1.8s | 比卡片晚、更慢，是「最后一层」 |

**节奏**（「平静」）
- 起步 320ms；相邻卡片间隔 `[300, 240, 200, 200, 220, 260]` ms，之后沿用最后一个值。先慢、中间顺、最后一条放慢收住：一次长呼吸。首屏约 3 秒走完。
- 图片显影时刻 = `max(卡片落稳时刻 + 单张时长×0.9 + 240ms, 上一张图的显影时刻 + 260ms)`：**一定晚于自己的卡片，且保持上下顺序**，不管网络谁先到。

## 五、新帖到达的动线（核心：不抢位置，点了才动，动得有秩序）
1. **在顶部之外往下刷时来了新帖**：不插队、不挪动正在看的内容；只在上方升起一枚胶囊「↑ N 条新动态」（32px 高，深底浅字；出现 0.7s 透明 + 0.9s 位移）。再来新帖，数字加一并轻轻鼓一下（缩放 1.06，520ms），不重新弹出。
2. **点胶囊**：胶囊先收起（0.4s 淡出 + 微缩）；页面平缓回顶，用时 `clamp(520, 380 + 距离×0.35, 1000)` ms，`easeInOutCubic`，距离越远越久；已在顶部（<6px）则不滚。
3. **腾位置**：新帖组放进一个 `overflow:hidden` 的容器，高度 0 → 实高一次平缓增长（时长 = 单张时长×700ms，缓动同位移）。旧内容整体轻轻往下滑一次，不会一条条顶着跑。
4. **依次亮起**：新帖按同一套节奏自上而下（最新的在最上），起步为首屏的 0.6 倍。
5. **认出新的几条（所有者说「看得不明显」后加的）**：新帖底色染一层新叶绿（`--new` 色，浅色 `#E4F1A6`、深色 `#34502A`，默认「中」档 11%）、左缘 1.5px 青柠线（`rgba(198,234,61,.7)`）、新帖组下方一条「刚到 N 条」细分隔线（11px，字距 .16em）。约 6.5 秒后底色和线用 3.2s 慢慢褪回卡片色，分隔线淡出。
   - 三档：微（只留左缘线）/ 中（默认）/ 显（底色 22%、线 2.5px）。
6. **别人的新帖不再用「…」气泡和弹簧过冲**，与首屏同一套节奏；**只有自己刚发的那条保留气泡**，作为你自己的那一下小确幸（弹簧过冲建议再收一点，1.28 → 约 1.08，另开 PR）。
7. 停在顶部时别人的新帖仍然先攒着、点胶囊才放进来：这是 #344 的既定决定，本次没改。

## 六、落地时必须守的规则（防踩坑）
- **只编排首屏**：屏外的卡片滚进视口时（`IntersectionObserver`，threshold .12）单张柔和上升，不排队；首屏只取 `offsetTop < 视口高 − 40` 的几条。
- **每条帖子只入场一次**：用已出现 id 集合（参考 #501 的 `SB_REV`，上限 400）；点网球、刷新、切筛选重画列表时，已出现过的直接就位，不重演。
- **高度从一开始就占好**：入场只动 opacity / transform / 底色 / 阴影，不改尺寸，下面内容不会被顶着跑。（腾位置那一次增长是唯一的例外，且只发生在用户主动点了胶囊之后。）
- **任何触摸 / 滚动立刻让路**：剩下的卡片马上就位（清掉定时器，补上终态）。
- **时间交给 CSS**：一帧内给每张卡片写好 `--d` 延迟，用 `transition-delay` / `animation-delay` 排程，浏览器按合成线程走；JS 只保留「图片到了」这一个必要的定时器。避免主线程忙时抖。
- **图先 `decode()` 再显影**，显影那一帧不卡；动画结束后撤掉 `will-change`，别长期占着合成层。
- **兜底**：6 秒后任何还藏着的卡片强制显示，内容不会一直停在隐藏状态；开了「减少动态效果」直接显示最终画面（含图片）；页面不可见、从后退缓存恢复时不播。
- 自己发的那条走原来的「发出去」动效，不进这套编排；`tmp:1` 的临时块不进入已出现集合，也不写进 `nbq_sb_feed` 缓存（见 #502）。
- 浅色 / 深色两套都要看：暖白在白卡片上看不见，所以光的颜色按主题取（见第四节）。

## 七、技术细节与踩过的坑
- **`overflow:hidden` 的 flex 子项会被压扁**（原型里踩到）：`.feed` 是纵向 flex，卡片自带 `overflow:hidden` 时最小高度为 0，会被挤成一条。必须给子项 `flex:none`。截图自查才发现，所以动效 PR 一定要出一张真实截图。
- **`color-mix(in srgb, …)` 做起始底色**：不用写两套色值，浅 / 深色自动适配；比叠一层半透明遮罩便宜，也不产生额外图层。
- **位移和透明度用两条缓动曲线**：位移「快起长尾」才有「放下」的物理感，透明度用柔和的对称曲线才不会闪。
- **所有时间乘同一个系数 `--k`**（原型里 0.5× / 0.25× 慢放就是改它），测试里也用它缩短时间。
- **别靠计时截图自查**：用 `document.getAnimations().forEach(a=>{a.pause();a.currentTime=t})` 定格（见 `动效与引导设计.md`）；CSS transition 也在 `getAnimations()` 里。
- **预览 / 评审方法**：做成「并排对比实验室」比单个原型有效得多：左右两部手机、同一时刻重播、可放大 / 慢放、一键走全流程，所有者可以直接说「左边那个 + 右边的节奏」。新的动效评审照此办。

落点（#501 分支 `side-reveal-soft`）：

- `src/shared/side/0030-照片.js`：图片显影改为「晚于自己的卡片、按上下顺序」，替换 #501 的到达序排队；
- `src/shared/side/0070-一个_App_实例.js`：`useFeed` 首次渲染后触发首屏编排；`flushNew` 改成「胶囊收起 → 平缓回顶 → 腾位置 → 依次亮起」；`insertPost0` 里别人的新帖不再走 `birth()` 的气泡。

测试（`tests/frontend/side_real.js` + 单测）：
1. 首屏卡片按上下顺序依次落稳（`--d` 单调递增，差值落在节奏表内）；图片显影时刻晚于所属卡片，且单调。
2. 慢网图片乱序到达，显影顺序仍按上下。
3. 每条只入场一次：点网球 / 重画后已出现的卡片不再带 `pre`。
4. 往下刷时来了新帖：`scrollTop` 不变、已有卡片位置不变；只出现胶囊，数字递增。
5. 点胶囊：回顶后新帖在最上、有新帖强调类；约 6.5s 后强调类被撤掉；旧内容高度和顺序不变。
6. 触摸 / 滚动让路；减少动态效果时直接终态；6 秒兜底。
7. 换账号 / 失败回滚时临时块与强调类被清理（沿用 #502 的测试思路）。
8. 真机：iPhone Safari、微信内置浏览器看流畅度（合成层与 `will-change` 的取舍）。
