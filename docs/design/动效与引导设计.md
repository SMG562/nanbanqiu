# 动效与引导设计（11-19 首页引导条「球场灯亮起」沉淀）

来源：首页引导条一整轮设计（7 版原型 + 正式代码，实现见 `src/shared/script/0502-首页引导条.js`、`src/shared/style/0330-首页引导条.css`，展示规则见 `0501`）。可播放的最终原型：`原型_球场灯引导条.html`（浏览器直接打开，顶部有电脑 / 手机、舒缓 / 紧凑、文案 A/B/C、自动消失开关）。
整体审美总纲见 `美学与品味.md`。做新的引导、欢迎、成功、节日类动效前先读这份；怎么一步步做见 `.claude/skills/nanbanqiu-motion-delight/SKILL.md`。

## 一、设计理念（为什么这样做）
1. **先问「这一刻用户心里是什么」，再写功能。** 想打球却没搭子的人要的是「有人、有地方、不尴尬」，不是「三步操作说明」。引导是给一种感觉，不是讲功能。
2. **一个场景，一件事，有因果。** 整条引导只讲一个小故事：夜里球场 → 球蹦进来 → 灯发现了它、慢慢亮起 → 光铺满 → 一句话。每一步是上一步的结果，不是并列的特效。
3. **克制，只留一个高光。** 高光是「灯被一点点点亮」；其余（场景、文字、颜色）都安静。苹果 / Google 的做法：动效服务于理解，物理感大于花哨，没有多余装饰。
4. **有等待，有静感，有呼吸。** 节奏比特效重要：开头静一拍、球落稳后再静半拍、亮完后停几秒再退场。留白就是高级感。
5. **主角始终最亮。** 暗场景里球保持原亮度，眼睛不用找。灯、光是配角，文字最后出现。
6. **场景固定，只变光。** 球场线、立柱、球的位置不再动；变化只来自「光」与「球的运动」。固定的背景让变化更有力。
7. **自己来、自己走，不欠用户。** 自动收起，不要求操作；往下滑、点任何东西都立刻让路；不重复打扰（每天每端一次）。
8. **文案不押注库存。** 球局少的冷启动期，「挑几场」「N 场在等你」会落空。文案只写情绪与邀请：「挑一场，加入。」「不用认识谁，来就好」。

## 二、设计语言
**颜色**（都来自网站主题）：夜色 `#041A12` → 主题深绿 `#0B3B2A / #12482F`；球场地面 `#164F35`、球场线 `#E8F1E9`（不透明度 .42，固定不变）；灯光暖白 `#FFF4C8` / 灯芯 `#FFF8DC`；强调青柠 `#C6EA3D`（小标题与「加入。」）；文字奶白 `#F7EBD6`。球 `#D0F04A` 系，永远是画面里最亮的一点。
**字**：系统无衬线（PingFang SC / Noto Sans SC），标题 700、字距 .04em、手机 22px / 电脑 32px；小标题 10.5–11.5px、字距 .16em、青柠色。真实站只能用系统字体，别依赖网页字体。
**形**：圆角 20px 的一整条；场景按固定比例（300:170）贴右，左边 24% 渐隐融进底色，不做硬分割；整条高度手机 124px / 电脑 156px，用完即收。
**动**：缓动只用少数几条（见下），时长偏慢（光铺开 4.4 秒、灯亮 3.2 秒），退场偏快（0.5–0.9 秒）。一切运动有物理依据（重力、惯性、光的扩散）。

## 三、节奏编排（舒缓版，ms）
| 时间 | 发生什么 | 为什么 |
|---|---|---|
| 0–900 | 全暗，静 | 让人安定下来，也让后面的动静有对比 |
| 900–2600 | 球从右边蹦进来跳四次，落在场地中线前 | 先给一个轻快的、可爱的主角 |
| 2600–3300 | 球落稳，再静半拍 | 呼吸；让「灯发现了球」成立 |
| 3300–6500 | 灯由暗到亮（单调上升）；光晕由小变大 | 高光时刻，必须平滑 |
| 3600–8000 | 光从灯处一圈圈推开夜色，回到主题深绿 | 「整个世界被点亮」 |
| 7000–8300 | 小标题与「挑一场，加入。」浮现 | 光到了才出字 |
| 约 +2.8s | 停留，灯光极轻地呼吸（亮度 92–100%，周期 6s） | 静感 |
| 退场 | 文字淡出 → 球滚出右侧、灯暗 → 整条折叠上移 | 自然消失，不突兀 |
提供「紧凑」版（时间 ×0.7）作对照；全部时间都乘同一个系数 K，便于测试缩短。

## 四、可复用的技巧
- **编排**：用 Web Animations API（`el.animate`）统一时间线，所有 delay / duration 乘系数 K；`fill:'both'` 让开场前保持起始姿态；`offset = t/总时长` 写关键帧。
- **弹跳的物理**：下落 ≈ 二次缓入 `cubic-bezier(.55,.085,.68,.53)`，上升 ≈ 二次缓出 `cubic-bezier(.25,.46,.45,.94)`；每次弹高 ×0.68（恢复系数），半程时长 ∝ √高度；落地挤压幅度 ∝ √弹高（并在起跳时轻微拉伸）；影子随高度缩小变淡；滚动角 = 水平位移 / 半径；越靠近镜头越大、落点越靠下（远小近大）。
- **光铺开**：夜色遮罩盖在场景上，用 `@property --nir`（`<length>`）注册的半径驱动 `radial-gradient` mask，半径从灯的位置 0 → 最远角；**主角（球）放在遮罩之上的独立图层**，所以一直是亮的。软边约 240px，别做硬边。
- **灯亮**：灯芯、光晕（scale .4→1 + opacity）、遮罩半径三条曲线都**单调上升**，用同一条缓动 `cubic-bezier(.4,0,.3,1)`；亮完后才开始很小幅度的呼吸。
- **文字浮现**：每行外层 `overflow:hidden`，内层 `translateY(110%) + blur(5px) + opacity 0 → 原位`，缓动 `cubic-bezier(.16,1,.3,1)`。
- **折叠退场**：外层 `grid-template-rows:1fr → 0fr`（带 opacity、margin 过渡），下面的内容自动上移，不跳。
- **分层与坐标冲突**：一个元素的 WAAPI 动画会覆盖 CSS transform；需要「平移 + 挤压 + 缩放 + 旋转」同时做时，用嵌套的 `<g>`（X 平移 → Y 平移 → 挤压 → 旋转），各自单独动画。
- **兜底**：`prefers-reduced-motion` 直接显示最终画面；页面不可见时先不开始（可见了才开始并记额度）；鼠标悬停暂停自动收起计时；存储失败时只在内存里记。

## 五、踩过的坑
- **「像电流闪了一下」**：我为了「呼吸感」在灯亮的过程里加了「亮一点 → 暗一下 → 再亮」，同时光铺开的半径也回缩了一下，三处叠在一起像接触不良。**由暗到亮的过程里不要有任何回头**；呼吸只在完全亮了之后、幅度小、周期长。
- **球太大 / 太小**：球径约为球场宽的 1/11 才协调；之前放大到抢了整个场景。尺寸要和场景里的参照物（场地、灯杆）一起看。
- **跳得不明显 vs 不自然**：加大弹高的同时必须遵守「越来越矮、越来越快、时长随高度缩短」，否则越明显越假。
- **用一个整体变亮的遮罩**会让球也变暗、看不清主角；要用分层。
- **每段关键帧各自带缓动**会让速度一顿一顿（每段起停）；整体用一条缓动放在时间参数里，只有物理弹跳这种分段运动才逐段设缓动。
- **文字出现得比光早**：文字在深色里先出现再被「换色」会闪；让文字在光铺满之后才出现，色值固定为最终色。
- **自查动画别靠计时截图**：截图有延迟，时间点不准。用 `document.getAnimations().forEach(a=>{a.pause();a.currentTime=t})` 逐帧定格再截。
- **「先静再动」的开场对第一次接触的人需要自信**：总长约 11 秒，所以一定要「任何操作都立刻让路」，并且每天只一次。

## 六、展示策略（产品侧）
每天每端（pwa / web）最多一次，所有人都看；显示时就记当天额度（不是等用户关掉）；分享 / 推送 / 球局链接进来不显示也不占额度；曝光够了把 `NBQ_INTRO_AUDIENCE` 改成 `'new'`（只给本机首次显示 14 天内的新用户）。本机记录 `nbq_intro = {v:2,first,days:{pwa,web},n}`。**不做曝光埋点**（所有者 11-19 定：不必要；效果靠现有的 session_start + game_view 对比整体变化）。

## 七、做新动效 / 引导时的检查清单
1. 这一刻用户心里是什么？一句话写下来。文案是否依赖库存、时间、数量？
2. 只讲一个小故事吗？每一步是上一步的结果吗？高光只有一处吗？
3. 主角始终最亮吗？场景是否固定、只变光和主角的运动？
4. 有静、有等待吗？总时长能否接受，任何操作能否立刻让路？
5. 有没有「回头」的变化（亮—暗—亮、放大—缩小—放大）？有就是闪烁，删掉。
6. 运动有物理依据吗（重力、惯性、扩散）？比例协调吗？
7. 减少动态效果、页面不可见、存储失败、窄屏、系统字体下都正常吗？
8. 先出静态图和可播放原型给所有者看，定了再进正式代码；测试里留「缩短时间」的钩子。

## 九、协作与工具方面的教训（这一轮的做法值得保留）
- **先出静态图 → 再出可播放原型 → 所有者拍板 → 才进正式代码。** 每一版只改所有者点名的那一处；他否掉的方向（如「浅色一行条」）不再提，他喜欢的（「原来的球场、灯光、球落下」）要原样保留。
- **所有者的话要按字面范围读**：「场景不要再变」= 球场线也不许变亮；「球一直亮」= 球不被遮罩影响；「就这版」= 不再自作主张加东西。我自己加的（呼吸的「微暗」、收起动画）要明说，让所有者决定留不留。
- **动画自查用定格**：`document.getAnimations()` 暂停并设 `currentTime` 逐帧截图；计时截图有延迟会看错。
- **脚本里含「remove / rm」一类字眼的长 Python / Bash 内联命令，可能被安全检查误拦**：改成先用 Write 写成文件再运行。
- **开 PR 要所有者明说**（会话规则）；仓库的收尾钩子会提醒「没有 PR」，那是提醒不是指令——先问，得到「开草稿 PR」再开。
- **预览站和真机必须看**：动画在 iPhone Safari / 微信里的流畅度、`@property` / `color-mix` 的支持我没法在沙盒里验证。
