## 规矩（机器拦得住的已经由测试拦，这里只留拦不住的）
1. **改令牌值 / 加令牌 = 同一个 PR 改 `前端风格.md` 的令牌表**，否则 CI 红。新代码只用标尺值，设计债预算只降不升（`tests/spec/design_budget.json`）。
2. **用户点评了图、页面或文案**：同一次回复里在 `决定记录.md` 追加一行；定下新角色 / 新场景范式 / 新画风：同一个 PR 补进 `角色与场景.md`，含「已否决」。
3. **文档里引用的仓库路径必须存在**（测试检查）；成品图只写图号和路径，不复制进来。
4. **改全局视觉（令牌值、品牌色、字体）必须真机看过**，PR 里写明手机端 / 网页端各看了没有；不确定的先出 2–3 个候选让所有者选，不替他定。
5. 发现某份文档和现实不符：以代码和成品图为准，当场改文档（`角色与场景.md` 末尾有已知过时清单）。
6. 新增一类设计知识（例如动效规范、插画规范）：在这里加一行索引，写成单独一份文档，别塞进技能里。
