# 交接协议（11-17 所有者定：每一次都按这个做，不只这一次）

**目标**：下一次对话**不读进度记录全文、不重新摸索**，用一句话起手就能直接开工。交接的质量标准 = 新对话第一条命令就是在做事，而不是在找上下文。

## 一、交接时按顺序做（缺一项不算交接完）
1. **下一步先写进 Issue**（事实来源；`进度记录.md` 只改长期事实，≤ 3 行）。Issue 正文固定五块：背景（一句）／范围与疑似位置（文件:章节，**用章节名不用行号**）／动手前先查什么／验收标准／做法提醒（指向技能章节，不复述）。
2. **现状一律实查，不转述记忆**：`bash tools/pr_state.sh <号> status`、`gh issue list`、`bash tools/handoff_check.sh`。交接里写的 PR / 分支 / CI 状态必须是刚查到的；判「做完 / 挡上线」先查代码里的开关、数据来源、前端实际调的接口（踩过：球拍在开关后却被当成上线门槛）；协作者读不到 Project 文档，排期只写进 Issue / 仓库，PR 正文 @ 对方（证据 #369 #371，11-18）。
3. **未完成的东西逐项列出并给出下一条命令**（例：「草稿 #328：`bash tools/pr_state.sh 328 ready` → `ci_wait.sh 328` → `pr_merge.sh 328`」）。
4. **经验教训进技能 / 文档，不进交接**：能复用的写进对应技能章节（仓库 `.claude/skills/`，唯一来源）；交接只留一行指针。
   - **新经验的流程（全自动，不靠人记、不靠人通知）**：经验 = 一个 PR：技能一行规则 + 证据 + 日期，能拦的写成钩子 / 测试，并在 `collaborator-pitfalls` §十 的闸门表加一行；合并后 `proposals.yml` 的 notify 自动在 #216 @协作者；两侧会话各写一行数字到台账 #349，周任务据此体检（有效 / 过时 / 单侧有效），候选删除只留言，所有者或协作者回复即可否决；加一条必须删一条没拦过事的旧条目。没有新经验就什么都不做。交接评论里固定写一行「**踩过的坑**：…」（没有写「无」），每周自动提炼从这一行取素材（collaborator-pitfalls §十一）。
5. **交接文档 ≤ 1.5KB**（Projects 里 `claude/交接_<日期>_<主题>.md`），只放：起点一句话、已合并 / 未合并（实查）、必读清单、不要读什么、开着的坑。**不写过程叙述**。
6. **最后一条回复**给所有者一段可直接复制的「起手提示」（见下），并说明「开新对话粘贴这一句」。

## 二、起手提示模板（放在代码块里，一句话 + 明确边界）
```
做 Issue #<号>。先读 `gh api repos/SMG562/nanbanqiu/issues/<号> --jq .body` 和 <技能名> §<章节>；不用读进度记录全文，不跑 handoff_check。完成标准见 Issue 验收。
```
注意：Claude Code 会话里 `gh issue view` / `gh pr view` 走 GraphQL 会 403，一律用 `gh api repos/…`（REST）。
要点：①任务 + Issue 号；②**具体**要读什么（命令 / 文件 / 章节）；③**明确不读什么**（进度记录全文）；④需要时加第一条命令。CLAUDE.md 已规定「开场点名任务就直接做」，所以这一句就够。

## 三、什么时候才需要读进度记录
只有所有者说「继续上次的」且**没点名任务**时：读 `进度记录.md` §0（约 2.4KB，`sed -n '/^## 0/,/^## 1/p' 进度记录.md`）+ `bash tools/handoff_check.sh`；不读全文。

## 四、控制长期成本（每次交接顺手做）
- `进度记录.md` 超过 15KB：把已完成的移到 `进度记录_历史.md`（文档整理，不动代码）。
- 不重复：同一事实只在一处写全，其余用指针（Issue 号 / 技能章节 / 文件路径）。
- 交接文档不累积：新的交接取代旧的同主题交接（旧的写一行「已取代」即可，不删文件）。

## 五、交接前自检（全部为是才说「已交接」）
□ 下一步在 Issue 里，且有验收标准　□ PR / 分支 / CI 状态是刚实查的　□ 未完成项各有下一条命令　□ 经验已进技能 / 文档　□ 给了所有者可复制的起手提示　□ 起手提示里写明了「不读什么」
