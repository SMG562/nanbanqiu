# 球局推广图指南（单局分享「球票」+ 每日 / 每周球局图）

> 球局推广图和海报不一样。海报卖的是情绪和品牌；**推广图卖的是「今天有球、还缺你」**，信息第一、好看第二。但它仍然是南伴球的脸，要守 `设计总纲.md` 的颜色、字体和落款规则。

---

## 一、两种图，分工

| | A 单局「球票」 | B 每日 / 每周球局图 |
|---|---|---|
| 谁发 | 发起人在 App 里点「发到小红书」 | 运营每天或每周发小红书、朋友圈、群 |
| 内容 | 一局：日期、时间、球场、类型、水平、缺几位、二维码 | 当天或本周的几局，加上「还有 N 局」和入口 |
| 在哪做 | App 代码（`src/`），html2canvas 生成 | `marketing/`，现在是模板 217（示意数据） |
| 改动流程 | 改 `src/` → `node tools/build.mjs` → `node tools/lint.mjs` → 测试 → 真机 | 跟海报一样：`build.py --only` |

## 二、A 单局「球票」（现状，改之前先读）

- **代码**：`src/shared/script/0180-…新手友好.js` 的 `ticketHTML()`、`xhsText()`；样式在 `src/shared/style/0110-分享图背面.css` 的 `.ogT` / `.t-*`；入口是 `src/pwa/script/0260-分享球员卡.js` 的 `openPoster()`。
- **结构**：
  - 左边主券占 72%，右边副券。
  - 主券顶上是一条 40px 的南伴绿抬头：图标、「南伴球」、城市网球约球。
  - 主券依次是：日期（小字、灰、字距大）→ 时间（30px 等宽粗体，最大）→ 球场（17px，最多两行）→ 胶囊「类型 · UTR」（浅绿底、绿字）→ 一条细线 → 「● 缺 N 位球友」（荧光点）。
  - 副券是米色底、虚线撕口加半圆缺口、二维码、「扫码加入」。
- **规则**（已在代码里，别改掉）：
  - 日期写具体的「11月9日 周日」，不写「今天」，因为发布和看到的时间可能不是同一天。
  - 二维码直达这一局。
  - 满员时写「已满员」。
  - 荧光点只出现在「缺几位」。
- **可以迭代的方向**（属于改 `src/`，要走「分支 → 预览站 → 真机 → PR」，先在 Issue 里提）：
  1. 主券加一个时段小标签（清晨、午后、夜场），夜场的抬头换深色。
  2. 女生局、新手友好局：在胶囊旁加一个标签，配色按总纲来，不用粉色刻板印象。
  3. 节令主题皮肤：只换抬头的底纹和一句小话（取自诗人打球系列），信息区一律不动。
  4. 保存的图片尺寸改成小红书 3:4。

## 三、B 每日 / 每周球局图（标准版式，见 217）

### 骨架（4:5，1080×1350；以后支持 3:4 时同比例拉长中区）

1. **抬头**（y 0–300，南伴绿，下沿一道浅弧）：
   - 第一行：荧光黄绿小字「11月9日 周日 · 墨尔本」。
   - 第二行：宋体大字「今天的球局」，周图用「这周的球局」。
   - 第三行：一句当天的小话，浅绿小字。
   - 右上角放一颗球和一个大圆，做装饰。
2. **球票列表**（y 340–1210，最多 5 张，每张高约 156，间距 20）：
   - 白卡，左右两段，中间虚线加缺口。
   - 左段：时间（56px 等宽粗体，最大）→ 球场（34px）→ 胶囊「类型 · UTR 范围」。
   - 右段：浅黄绿底，荧光点加「缺 N」（38px 绿）和「位球友」。
   - 按时间排序。
3. **底栏**（y 1240–1340）：
   - 左边：「还有 N 局，按水平和距离筛」和「扫码打开南伴球 · 申请就能加入」。
   - 右边：落款加二维码。

### 数据规则（最重要）

- **只用真实数据**，从正式库只读查当天或本周的公开球局。示意图必须 `demo=True`。
- **不出现任何用户信息**：名字、头像、性别、电话都不要（`隐私清单.md`）。只写球局本身的信息。
- **球场名**：真实发布时写球局里的公开球场简称，示意图用虚构的名字。
- **挑哪几局**：
  1. 还缺人的优先。
  2. 时间分散（早、中、晚各有）。
  3. 水平分散。
  4. 满员的不放。

  放不下的写进「还有 N 局」。
- **数字诚实**：
  - 局少（1–2 局）时不硬撑，标题改成「今天还缺你」，并放大那一两张。
  - 0 局时换成小毛空状态的那一句「该你发球了。」，配「发一局」的入口。
  - 不编「很多人想打」这类没有数据支撑的数字。

### 每天一句的小话（文案池，按星期、天气、时段挑；不重复用到烂）

- 早场多：「春眠不觉晓？早场七点见。」「早起的人先占到场。」
- 周末：「周六空着，就约一局。」「两个人，就能开一局。」
- 雨后：「雨停了，场还在。」「下雨也去，谁怕？」
- 夜场多：「灯比我先亮。」「打到天黑，也不想回家。」
- 高温 / 大风：「今天风有点大。」「今天 38 度，挑晚场。」
- 节令：从 `系列_诗人打球.md` 取当季那张的大白话。

规则同总纲：陈述句、句号收尾、不用感叹号。

### 变化与系列感

- 骨架、颜色、字号永远不变，这样用户在信息流里一眼认得出「这是南伴球的每日图」。
- **只换两样**：抬头那句小话，和右上角的装饰（平时一颗球；节令换诗人系列的小元素，比如月、菊、灯笼）。
- 周图：标题「这周的球局」，按天分组，每天一行小日期加 1–3 张票。最多 7 张，放不下写「还有 N 局」。

## 四、怎么做出来（现在 → 以后）

- **现在**：
  1. 复制 `marketing/posters/p217_daily_games.py`，把 `GAMES` 换成当天的数据（只读查库，不写库）。
  2. 改 `demo=False`，再跑 `build.py --only`。
  3. 发布前过一遍 §三 的数据规则和总纲 §八 的自检。
- **以后（要做就先开 Issue）**：写一个 `marketing/daily.py`，用只读接口拉当天球局，一条命令出图，输出 4:5 和 3:4 两种。二维码用 App 里同一个 `qrSVG` 的逻辑，指向发现页。这属于新工具和新依赖，按 CLAUDE.md 先问。

## 五、推广图自检

1. 三秒内能看出「哪天、几点、在哪、缺几个」吗？时间是不是最大的字？
2. 荧光色只给了「缺 N」和球吗？
3. 有没有任何用户个人信息？数字都是真的吗？示意图标了 demo 吗？
4. 二维码能扫吗？指向的地方对吗？
5. 和昨天的图比，骨架一致吗？只换了小话和装饰吗？
