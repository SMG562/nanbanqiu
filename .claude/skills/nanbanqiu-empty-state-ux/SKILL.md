# 南伴球空状态 / 提示设计

来源：11-04 一整轮设计，所有者连续说「非常棒」。仓库里有 36 个现成图标和文案表：`marketing/icons/README.md`（**先读它**，再决定要不要新画；画风首选 `marketing/icons/舞台风/`）。

## 一、一句话公式
**空和错的时候，不说「没有」，说一句只有打网球的人才懂的话，让人会心一笑；再用一句副句递出下一步。**
- 双关优先：发球 = 发布球局、出界 = 球局不存在、断线 = 拍线 / 网络、开罐 = 更新、热身 = 加载、捡球 = 列表到底、拍线 = 调试。
- 例：「该你发球了。」「这局飞出界了。」「断线了。」「热身中。」「换新球了。」「球都检完了。」「听着呢。」「条件有点挑。」
- 规则：陈述句、句号收尾、无感叹号、不说教、不「A，才B」、不承诺没确认的功能；爱调侃但不责备用户（爆约、迟到用「球等了你一会儿。」这类温柔说法）。最后过一遍：删掉图，文字也要立得住。

## 二、图标画法
- 小毛 = `mao3.figure3`（立体球 + `face2` 脸）+ **流畅单笔细线手脚**（不用 `pen` 的重影和 `rough2` 抖动；所有者说过「太像手写、不流畅」）。
- viewBox 220×220、球半径 42、地面 y=198；一个动作 + 一个道具，极简；小尺寸（84px）也要认得出。
- 生成脚本在 `marketing/icons/`（`helpers.py` 共用，`gen_set*.py` 出图）。动效在 App 里用 CSS（摆铃、飘音符、颠球），不用 GIF。

## 三、用户心理（空状态最大的风险：用户觉得「这个 App 没人」然后走了）
1. 减失落：用一个笑把失落换掉。
2. 证明社区是活的：马上展示别的日子或放宽条件后有球局。
3. 降低发局成本：预填上一局的时间 / 球场 / 人数，一键发出。
4. 留住回来的理由：「有球局就通知我」。
5. 「我也想打」要后端数据够了再上；**没有真实数据的数字（想打人数、附近有人）一律不显示**。

## 四、筛选后没有球局 = 自适应，不写死一句话
1. 回显用户自己的条件（可点掉的小标签），告诉他「为什么没有」。
2. 对每个条件**单独放宽一档**并数球局：距离 5→10→20 km；水平只放半档；类型 / 标签→不限；日期→最近有球的日子。
3. 只展示**真的有球局**的前两项，按「球局数多、改动小」排序；同分顺序：距离 → 日期 → 类型 → 水平（水平最后，不推荐水平差太远的局）。
4. 单项都是 0，才试**放宽两项**；两项还是 0，才走「附近真的没有」：发球图标 + 发一局 + 通知我。
5. 有建议时「发一局」是次按钮，没建议时才是主按钮；小毛的状态跟着情形变（放大镜 / 一摊手 / 发球）。

## 五、文案池
同一场景准备 3–5 句，按时段 / 星期 / 天气 / 里程碑选一句：清晨「这么早，只有鸟醒着。」、周六「周六还空着。」、深夜「灯亮着。」、高温「今天 38 度。」、风大「今天风有点大。」。基调要帮忙、贴墨尔本的生活，不要刻意。

## 六、接入 App 时
- 只改 `src/`；网页端和手机端空状态代码有两处重复，先抽共用函数。
- 所有者明确说过的要求先写成测试（断言 DOM，不只断言内存）；前台状态看页面（见 `frontend-state-ui-consistency`）。
- 图标用 SVG symbol 内联（不要外链图片），动效用 CSS，尊重 `prefers-reduced-motion`。

## 七、迭代方式
- 每轮出多个方向让所有者选，附「解决什么心理问题」的一句话；选定后只改被点名的细节。他说「奇怪 / 不自然」先判断是材质过度还是比例问题，往简化退一步。
- 品牌视觉、海报类请读 `.claude/skills/nanbanqiu-poster/SKILL.md`，不要在这里重做。
